### Sujets du IF (op 0x02) — dispatch interne

Résolution de "sujet-valeur" commune (cas 0, 4, 7, 20 ; tables byte_48A4A4/4E8/52C/588 identiques, index `param2-0xC8`) : **0xC8→self ; 0xCB→last_attacker_slot_id ; 0xDC–0xE3→BATTLE_LOCAL_VAR[52*slot+code] ; 0xC9/0xCA/0xCC–0xDB/défaut→scan com_file_id (introuvable→255)**.

## 5. Le commit d'action (LABEL_375 @ 0x48983D) — FACT

1. `slot.target_info_mask = target_info_mask` (registre VM → slot).
2. **Fold du masque par défaut** : cmd==2 → `| ComputeMaskFromDefaultTarget(K_MAGIC[section].defaultTarget)` ; cmd==4 → `| …(K_ITEM[section].targetInfo)` ; sinon → si `K_ENEMY_ATTACK[section].attackFlags & 0x80` → `| 0x4000`.
3. `BattleAction_GetText(slot, cmd, section, has_text_pending, enter_alt_target_param_2, mask, ai_scratch_var)` (7 args, le 7e = anim).
4. `BattleAction_ResolveTargetAndHitCount(mask)`.
5. Si `BOOL_TARGET_CHOOSEN` → **return** (suspension).
6. Sinon : SetPhase(5) ; EnqueueActionPresentation(ATTACK_HIT_COUNT-1) ; `ACTION_EVENT_GROUP_INDEX[20*ATTACK_HIT_COUNT]=0` ; si `BACK_PREEMTIVE_INFO_3` → **follow-up Odin/Gilgamesh** : mask = ComputeMask(K_MAGIC[byte_1D28DCD].defaultTarget) | ResetExecState(byte_1D28DCE) ; GetText(slot, 0xF7|2, byte_1D28DCD, 0,0, mask,0) ; Resolve ; SetPhase 5/6 ; clear BACK_PREEMTIVE_INFO_3 et byte_1D28E0D ; puis SetPhase(6) ; `EnemyAI_SyncAIVarsToSlot(slot)` ; **retour à la boucle** (le script continue après le commit !).

**Points clés** : le commit n'arrête **pas** la VM (sauf target-choosen) ; plusieurs commits peuvent donc survenir dans une même exécution de script (0x1B commit inline puis continue aussi).

## 6. RNG (FACT)

Tout passe par `domain::Battle_GetRandomInt()` (RNG battle-local, curseur `BATTLE_RNG_LANE_INDEXES[BATTLE_RNG_ACTIVE_LANE]`, pas de CRT) :
- Pré-boucle Berserk : `%3` re-tiré tant que mort (consomme un nombre **variable** de tirages).
- 0x0B : 1 tirage `%3`.
- 0x04 codes 0xC9/0xCA/0xCF : re-tirage en boucle (consommation variable).
- IF sujet 0x02 : 1 tirage `%param`.
- 0x29 : 1 tirage (via SelectRandomMagicFromPlayer) ; 0x2E : 2 tirages (+ SelectRandomMagicFromStock).
- **Ordre des effets de bord RNG = ordre d'exécution des opcodes** — important pour le déterminisme/RNG-manipulation.

## 7. Subtilités signed/unsigned, masques, pointeurs (endroits où Hex-Rays peut masquer)

1. **`0x3C MOD_HP_SELF` signé** : `movsx ecx, cx` — Hex-Rays le montre mais le type `unsigned __int16` du local peut induire en erreur ; le delta est **int16**.
2. **`0x23 JUMP` signé** : la double écriture `word ptr [jump_value], dx` puis lecture `test ah,80h` + `or eax,0FFFF0000h` — Hex-Rays fusionne en `jump_value | 0xFFFF0000` mais **la partie haute de `jump_value` (32-bit) peut contenir des résidus** des usages précédents (0x0B y stocke un id d'abilité en LOWORD) — le `and eax,0FFFFh` avant le `or` protège, mais l'écriture `word ptr` ne clear pas le haut : comportement net correct, source de confusion.
3. **Masque 0xCA "aucun monstre" = 8** (`1<<3`, slot 3) vs 0xC9 "aucun" = 0 — asymétrie délibérée ou bug original, à conserver telle quelle.
4. **`0x04` défaut introuvable → `0x80000000`** : `mov ecx,0FFh; shl eax,cl` — décalage 32-bit non masqué sur ce chemin (contrairement à 0x2B où `shl eax,cl` avec cl=slot est masqué à 5 bits par le CPU). Résultat observable : bit 31.
5. **Sujet 0x0A élément (cas 5)** : `shl eax, cl` avec cl = byte bas de value → décalage **mod 32** silencieux ; value ≥ 32 wrappe.
6. **`0x25 SCAN_STORE` direction du memcpy** : dst = pointeur texte résolu, src = BMI_SCAN_BUFFER (ordre des push : `18h`, `edx`(src), `ecx`(dst)) — le commentaire IDA existant dit l'inverse ; **ne pas faire confiance au commentaire**.
7. **Sujet 0x0A cas 0xCB** : le `cmp cx, 0C8h` du listing est en fait un test contre **200** (0xC8 = 200 = code "équipe") : si param==200 → sujet = self, sinon scan com_file_id. Hex-Rays mélange les deux constantes (0xC8 symbolique vs 200 décimal).
8. **`0x11 SET_ITEM_SLOT` écrit un DWORD** (`SG_ITEM_ID_AND_QUANTITY[2*idx+48].id` = 4 octets) alors que la structure est décrite en paires id/quantité — l'écriture 32-bit écrase potentiellement id+quantité d'adjacents selon le layout réel ; à vérifier avec la taille réelle de la structure.
9. **`0x0B` : relecture des opérandes comme tableau** via des slots stack contigus — si on réordonne les locals dans un rewrite, ceci casse.
10. **Sujets IF avec cmp hors domaine → toujours saut** (pas de no-op !) : différence comportementale cruciale vs le défaut de l'étage opcode (qui est no-op).
11. **`0x36`** : `and dl, 0FDh` (listing) — le commentaire dit `&0xF5` ; les deux clear le bit 1 et le `or 8` set le bit 3 ; différence sur bit 2 (0xFD le garde, 0xF5 le clear) — **à trancher sur l'octet exact du `and`** (j'ai vu `0FDh` dans le listing fourni, le commentaire IDA dit 0xF5 ; l'un des deux est faux).

## 8. Ambiguïtés restantes et où les lever

1. **`EnemyAI_GetSubjectValue_D`** (sujet 0x14) : sémantique du per-membre — examiner la fonction (appelée avec `(0, value, &slot.status_1-0x80)`) ; le pointeur `-0x80` depuis status_1 (slot+0x80) → slot base → probablement une lecture de champ du slot dépendant de `value`. → **décompiler le callee**.
2. **`byte_1D28DCD/byte_1D28DCE`** (follow-up Odin) : qui les écrit ? → **xrefs_to** sur ces deux globals ; vraisemblablement le handler de mort d'Odin/Gilgamesh.
3. **Champ `[com_file_id-0x3B]`** (sujet 0x09) : déterminer l'offset réel de com_file_id (scan sentinel 0x1D2817B, base 0x1D27B10, stride 0xD0) pour identifier le champ (probablement un flag "inactif/absent" du slot). → **get_bytes sur les opérandes `offset BATTLE_SLOT_DATA.com_file_id`** dans le désassemblage.
4. **`0x36` masque exact** (0xFD vs 0xF5) : → **get_bytes à l'adresse du `and`** (~0x489E9D).
5. **Layout exact `slot.set_zero[code*2-0x698]`** (0x04 cas 0xDC–0xE3 et sujet 0xDC–0xE3) : les deux formules (`[eax+ecx*4-34Ch]` word vs `[eax+ebp*4-34Ch]` dword) suggèrent une zone de stats/dwords à slot+0x64.. ; → **comparer les deux chemins et la structure**.
6. **Sémantique fine des relays 0x69/0x6A/0x70/0x71** : le mécanisme (ActivateTargetRelay + callback + écriture dans le résultat) est FACT ; le rôle précis de chaque relay (caméra, barrier de présentation, enter-anim) reste SI — → **examiner BattleEvent_ActivateTargetRelay et la file d'événements**.
7. **`AI_VM_FALLBACK_BYTECODE`** : rempli de 0xFF dans le fichier — c'est une zone **écrite en runtime** ; → **xrefs_to 0x1D2A21D** pour trouver le producteur (probablement l'init de battle qui y écrit `0x0C 0x00` = USE_ABILITY(0) + STOP, ou similaire).

## 9. Pseudo-C fidèle de la boucle et du dispatch

```c
/* Fidèle au comportement original — pas de modernisation.
   Types et noms = ceux observés dans l'asm. */

unsigned __int8 EnemyAI_VM_ExecuteScript(
        unsigned int   p_ai_subsection_init_code,   /* ebp (déplacé) */
        unsigned int   p_monster_slot_id,           /* ebx */
        unsigned __int8 *p_ai_current_subcode,      /* esi */
        int            p_text_subsection,
        int            p_text_offset_section)
{
    unsigned __int8 *pc;
    unsigned __int8  op, a1, a2, a3;
    unsigned __int16 val16, jmp16;
    int  cmd = 0;                 /* command_type        */
    int  section = 0;             /* section_position    */
    int  mask = 0;                /* target_info_mask    */
    unsigned __int8 scratch = 0;  /* ai_scratch_var      */
    unsigned __int8 alt_p2 = 0;   /* enter_alt_target_param_2 */
    unsigned __int8 has_txt = 0;  /* has_text_pending    */
    int  rank = BMI71_LOW_MED_HIGH_LEVEL_BIS[71 * p_monster_slot_id];
    int  info = *(int *)*(int *)&BATTLE_SLOT_DATA[p_monster_slot_id].monster_info_section;
    int  row;

    /* --- pré-boucle Berserk (section 1 uniquement) --- */
    if (AI_CURRENT_SECTION_INDEX == 1
        && (BATTLE_SLOT_DATA[p_monster_slot_id].status_1 & 0x20))
    {
        if (EnemyAI_CountAlivePartyMembers() == 255) {
            mask = 0; a1 = 0;
        } else {
            int t;
            do { t = Battle_GetRandomInt() & 0xFF; } while (t % 3, 0); /* cf. asm */
            do { t = (unsigned __int8)Battle_GetRandomInt() % 3; }
            while (BATTLE_SLOT_DATA[t].status_1 & 1);
            mask = 1 << t; a1 = 0;
        }
        pc = &AI_VM_FALLBACK_BYTECODE;
        goto use_ability_row;            /* LABEL_372 */
    }
    pc = p_ai_current_subcode;
    goto parse_next;

use_ability_row:                          /* 0x489804 */
    row = 16 * rank + a1;
    cmd     = *(unsigned __int8 *)(info + 4 * row + 0x34);
    section = *(unsigned __int16 *)(info + 4 * row + 0x36);
    scratch = *(unsigned __int8 *)(info + 4 * row + 0x35);
    /* fallthrough LABEL_373/374 */

execute:                                  /* op 0x06 -> LABEL_373 */
    if ((unsigned __int16)section == 0)
        goto parse_next;

commit:                                   /* LABEL_375 @ 0x48983D */
    {
        int m = mask;
        BATTLE_SLOT_DATA[p_monster_slot_id].target_info_mask = (unsigned __int16)mask;
        if (cmd == 2)
            m |= BattleTarget_ComputeMaskFromDefaultTarget(
                     K_MAGIC[(unsigned __int16)section].defaultTarget);
        else if (cmd == 4)
            m |= BattleTarget_ComputeMaskFromDefaultTarget(
                     K_ITEM[(unsigned __int16)section].targetInfo);
        else if (K_ENEMY_ATTACK[(unsigned __int16)section].attackFlags & 0x80)
            m |= 0x4000;
        mask = m;
        BattleAction_GetText(p_monster_slot_id, cmd, section, has_txt,
                             alt_p2, m, scratch);
        BattleAction_ResolveTargetAndHitCount(m);
        if (BOOL_TARGET_CHOOSEN)
            return BOOL_TARGET_CHOOSEN;               /* suspension */
        BattleState_SetPhaseFlag(5);
        BattleEvent_EnqueueActionPresentation(ATTACK_HIT_COUNT - 1);
        ACTION_EVENT_GROUP_INDEX[20 * ATTACK_HIT_COUNT] = 0;
        if (BACK_PREEMTIVE_INFO_3) {
            /* follow-up Odin/Gilgamesh — cf. asm 0x48A026..0x48A091 */
            ...
            BACK_PREEMTIVE_INFO_3 = 0; byte_1D28E0D = 0;
        }
        BattleState_SetPhaseFlag(6);
        EnemyAI_SyncAIVarsToSlot(p_monster_slot_id);
        goto parse_next;                              /* le script CONTINUE */
    }

parse_next:                               /* 0x487EBA */
    op = *pc++;
    if (op == 0)
        return 0;                                     /* STOP */

    switch (op) {
    case 0x0A: case 0x10: case 0x14: case 0x21:
        goto parse_next;                              /* NOP (table @0x48A0B8) */

    case 0x02: { /* IF : subj, param, cmp, value(2), jump(2) */
        unsigned __int8 subj = pc[0], param = pc[1], cmp = pc[2];
        unsigned __int16 value = pc[3] | (pc[4] << 8);
        unsigned __int16 jump = pc[5] | (pc[6] << 8);
        int cond;
        pc += 7;
        if (subj > 0xE3) goto parse_next;             /* sujet hors table -> IF ignoré */
        cond = eval_if_subject(subj, param, cmp, value); /* cf. tables 0x48A204/0x48A308 */
        if (!cond) pc += jump;                        /* saut si FAUX (u16, forward) */
        goto parse_next;
    }

    case 0x23: { /* JUMP */
        signed short off = pc[0] | (pc[1] << 8);
        pc += 2;
        pc += off;                                    /* signé : arrières possibles */
        goto parse_next;
    }

    case 0x0B: { /* USE_RANDOM_ABILITY_3 */
        unsigned __int8 tri[3]; tri[0]=pc[0]; tri[1]=pc[1]; tri[2]=pc[2]; pc += 3;
        int r = (unsigned __int8)Battle_GetRandomInt() % 3;
        if (tri[r] == 0xFD) goto parse_next;          /* 253 = skip */
        row = 16 * rank + tri[r];
        cmd     = *(unsigned __int8 *)(info + 4*row + 0x34);
        section = *(unsigned __int16*)(info + 4*row + 0x36);
        scratch = *(unsigned __int8 *)(info + 4*row + 0x35);
        goto execute;                                 /* LABEL_374 */
    }

    case 0x0C: { /* USE_ABILITY */
        a1 = *pc++; row = 16 * rank + a1;
        cmd     = *(unsigned __int8 *)(info + 4*row + 0x34);
        section = *(unsigned __int16*)(info + 4*row + 0x36);
        scratch = *(unsigned __int8 *)(info + 4*row + 0x35);
        goto execute;
    }

    case 0x03: cmd = 2; section = *pc++;                       goto parse_next;
    case 0x07: cmd = 8; section = *pc++;                       goto parse_next;
    case 0x05: scratch = *pc++;                                goto parse_next;
    case 0x06: goto execute;
    case 0x2A: cmd = 2;
               section = BATTLE_SLOT_DATA[p_monster_slot_id].magic_to_blow_away;
               mask = EnemyAI_GetTargetMaskFromMask(
                          BATTLE_SLOT_DATA[p_monster_slot_id].magic_to_blow_away);
               scratch = 0x0B;                                 goto execute;
    case 0x1E: cmd = 0xFC; section = 1; alt_p2 = *pc++;        goto commit;
    /* ... 55 autres cas : cf. table section 4, transcrits 1:1 ... */
    default:   goto parse_next;                                /* op > 0x3D */
    }
}
```

`eval_if_subject` reproduit le double dispatch : table `byte_48A204[subj]` → famille (0=HP, 1/5=statut groupe, 2=RNG, 3=scene, 4=statut slot, 6=nb vivants, 7=niveau, 8/9=présence, 0x0A=dernier attaquant (+ table `byte_48A308[param]`), 0x0E=rank, 0x0F/0x10/0x11/0x12/0x13=booléens, 0x14=tous-membres, 0x12=item, 0x13=battle var, 0x14=local var), comparateurs 0==,1<,2>,3!=,4<=,5>=, **saut si faux**, booléens n'acceptant que cmp∈{0,3} (sinon toujours faux).

## 10. Résumé architectural

- **Interpréteur à registre unique (PC=ESI)**, bytecode octet, opérandes inline LE, 61 opcodes + STOP, dispatch par jumptable indexée `op-1`.
- **Modèle à deux phases** : la plupart des opcodes *préparent* (registres VM : cmd/section/mask/scratch) ; le commit (0x06 EXECUTE, ou directement via 0x0B/0x0C/0x1E/0x2A/0x1B) *exécute* via GetText+ResolveTargetAndHitCount, puis **rend la main à la boucle** (un script peut committer plusieurs actions).
- **Flux de contrôle** : uniquement 0x23 (inconditionnel signé 16) et 0x02 (conditionnel, saut-avant u16 si faux) ; pas de call/return VM, pas de boucle native — les boucles sont émulées par JUMP négatif.
- **État** : locals VM (transitoires, réinitialisés à chaque appel — donc un script qui "prépare" puis atteint 0x00 **perd** sa préparation), BATTLE_LOCAL_VAR (52 dwords/slot), BATTLE_BATTLE_VAR (globales), slots de battle (HP/ATB/status/flags), savemap (items/GF/Odin), files de drops.
- **Suspension** uniquement via `BOOL_TARGET_CHOOSEN` (return non-zéro) ; la reprise est à la charge du caller (`EnemyAI_DispatchSection`, 4 sites d'appel), qui rappellera vraisemblablement avec un sous-code différent — **à confirmer en examinant ces 4 call sites** pour lever la dernière ambiguïté sur la sémantique du retour.
