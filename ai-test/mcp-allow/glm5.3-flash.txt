## 2. Mécanisme de lecture des opérandes

Tous les handlers avancent `esi` (le pointeur bytecode) **eux-mêmes**, octet par octet, avec des `movzx`/`and 0xFF` systématiques. Les mots 16 bits sont assemblés **little-endian à la main** : `lo + (hi << 8)` (ex. 0x488794–0x4887AA pour IF, 0x4897C5 pour JUMP, 0x488744 pour SET_RES_FIELD, 0x489F30 pour MOD_HP_SELF). Aucune lecture alignée : impossible de désynchroniser le décodeur autrement qu'en sautant au milieu d'un opérande (ce que permet justement JUMP/IF — c'est un saut relatif brut de `esi`, voir §5).

## 4. Op 0x04 CHOOSE_TARGET — codes de cible (FACT, table 0x48A61C + handlers)

| Code | Signification | Masque résultant |
|------|---------------|------------------|
| 0x00–0x07 | slot direct | `1 << code` |
| 0xC8 | self | `1 << slot` |
| 0xC9 | PJ vivant aléatoire | boucle `rng%3` tant que mort ; 0 si aucun vivant |
| 0xCA | ennemi vivant aléatoire (slots 3–6) | `(rng & 3) + 3` tant que mort ; `8` si aucun (⚠ masque `1<<8`=0x100, hors slots) |
| 0xCB | dernier attaquant | `1 << slot.last_attacker_slot_id` |
| 0xCC | tout le party | `0x8007` |
| 0xCD | tous les alliés | `0x80F8` |
| 0xCE | tous les slots | `0x80FF` |
| 0xCF | allié (ennemi 3–7) aléatoire ≠ self | si `GetTargetMemberCount(201)==1` → self ; sinon boucle rng |
| 0xD0 | variante party | `0xA007` |
| 0xD1 | dernière cible visée | `1 << ATTACKER_SLOT_ID_0+3` |
| 0xD8–0xDF | slot depuis `BATTLE_LOCAL_VAR[52*slot + code-0xD8]` (u16) | `1 << var` |
| 0xE0–0xE3 | idem (4 codes supplémentaires) | `1 << var` |
| autre | recherche `com_file_id == code` sur les 8 slots (stride 208) | `1 << slot` ; échec → `mask = 1<<255` (0x80000000) et **continue** |

**FACT** pour la structure ; l'interprétation sémantique des noms ("party", "alliés") est SI (cohérente avec les commentaires G15/G22 et `TargetHasStatus` : 200=party 0–2, 201=monstres 3–6).

## 5. Op 0x02 IF — sujet, comparateur, saut (FACT)

Format : `subj(1) param(1) cmp(1) value(2) jump(2)`. Si `subj > 0xE3` → no-op. Sinon `handler = byte_48A204[subj]` (table vérifiée) puis switch interne. **Sémantique générale : si la condition est FAUSSE → `esi += (u16)jump`** (les comparateurs sont donc "continuer si vrai").

Comparateur (partout où `EnemyAI_CompareValues` est utilisé, vérifié 0x48A680) : **0 = ==, 1 = <, 2 = >, 3 = !=, 4 = <=, 5 = >=** (comparaison **non signée**). cmp>5 → saut inconditionnel (default). Exceptions : sujet 4 (statut) n'accepte que cmp 0 (présent) et 3 (absent) ; cmp autre → saut.

Sujets actifs (après table) :
- **0** : HP d'un slot résolu (param : 0xC8 self, 0xCB dernier attaquant, 0xDC–0xE3 var locale, sinon com_file_id) ; `value` 1–9 → seuil `value * max_hp/10` (division magique 0x66666667, **arithmétique signée** sar) ; `value==10` → `max_hp/4` ; sinon comparaison directe via `CompareValues` (non signée).
- **1** / **5** : `EnemyAI_TargetHasStatus(param, cmp, value, 0/1)` — compte de cibles avec statut (0 = "au moins une", 1 = variante forme d'équipe, retour booléen inversé).
- **2** : **RNG** — `GetRandomInt() % param` comparé à `value` (probabilité ; `idiv` signé mais opérandes ≥ 0).
- **3** : `COMBAT_SCENE_ID (u16)` vs value.
- **4** : bit de statut du slot résolu : `value<16` → `status_1`, sinon `status_2` bit `value-16`.
- **6** : `GetTargetMemberCount(param)` vs value.
- **7** : `slot.level` vs value.
- **8** / **9** : existence d'un slot avec `com_file_id==value` (9 : et vivant) ; cmp 0/3 seulement.
- **0x0A** : famille "dernier attaquant" avec sous-dispatch sur `param` : 0=`last_attacker_attack_type`, 1=`last_attacker_is`, 2=`number_turn`, 3=`last_attacker_command_type`, 4=`last_attacker_action_or_gf_used`, 5=bit `value` dans `last_attacker_attack_element`, 0xCB=`last_attacker_slot_id` vs value (200→self, sinon scan com_file_id).
- **0x0B–0x11** (via sujets 0x0E–0x14) : idem champs last-attacker en accès direct.
- **0x12** (sujets 0x50–0x57) : `SG_ITEM_ID_AND_QUANTITY[subj]` vs value.
- **0x13** (sujets 0x60–0x67) : `BATTLE_BATTLE_VAR[subj]` vs value.
- **0x14** (sujets 0xD0–0xD7) : somme de `GetSubjectValue_D(0, value, &slot[i])` sur les PJ vivants ≠ 0.
- Sujets mappés vers **0x15** (0x0B–0x0D, 0x15–0x4F, 0x58–0x5F, 0x68–0xC7, 0xC9–0xCF, 0xD8–0xE3) : **no-op** (le switch interne n'a pas de case 0x15 → default → continue sans saut).

⚠ **Piège Hex-Rays** : dans le switch interne, les `case 0x50–0x57 / 0x60–0x67 / 0xDC–0xE3` du pseudo-C semblent accessibles, mais le sélecteur réel est la **valeur mappée** (≤ 0x15) : ces cases sont **mortes** ; ce sont les sujets *originaux* 0x50–0x57 etc. qui, une fois mappés à 0x12/0x13/0x14, indexent les bons tableaux (`opcode_param_1` conservant le sujet original). **FACT** (table 0x48A204 entièrement ≤ 0x15, vérifiée).

## 6. RNG — usages exacts (FACT)

Primitive unique : `domain::Battle_GetRandomInt` (0x48F020) — lit `RANDOM_NUMBER_LIST` au curseur `BATTLE_RNG_LANE_INDEXES[BATTLE_RNG_ACTIVE_LANE]` et incrémente. Aucun CRT. Appels :
1. Prologue berserk : choix d'un PJ vivant (`% 3`).
2. IF sujet 2 : probabilité (`% param`).
3. Op 0x0B : choix d'abilité (`% 3`).
4. Cibles 0xC9 / 0xCA / 0xCF (choix aléatoire pondéré par les vivants, avec re-tirage sur mort).

Chaque appel consomme un octet de la liste — les scripts IA sont donc **reproductibles/rerollables** au frame près (pertinent pour TAS/seed).

## 7. Signed/unsigned, bitmasks, conversions — subtilités (FACT)

- **JUMP/IF** : offset lu comme u16 puis, pour 0x23, test du bit 15 → extension signée (`| 0xFFFF0000`). Dans IF, l'addition `esi += (u16)jump` est **non signée** : un offset "négatif" dans IF avance quand même (bug ou non-testé — les scripts réels utilisent 0x23 pour les sauts arrière). À vérifier dans les données de jeu.
- **`idiv 3` / `idiv ecx`** : division **signée** ; les dividendes sont masqués `& 0xFF` avant → toujours positifs, pas de souci.
- **HP% (IF sujet 0)** : `max_hp/10` via `imul 0x66666667; sar 2` — arrondi **vers zéro signé**, mais `max_hp` est positif ; la comparaison finale passe par `CompareValues` **non signée**.
- **Op 0x3C** : `movsx ecx, cx` → delta **signé 16 bits** appliqué à `current_hp` (dword) : peut descendre sous 0 sans clamp dans le handler (clamp ailleurs ? à vérifier).
- **Op 0x2B** : `1 << slot` sans bornes : slot ≥ 8 produit des bits 8–12 du masque cible (note G08 fail-closed).
- **Cible 0xCA sans ennemi** : masque `1 << 8` = 0x100 — valeur sentinelle qui sort du champ des slots.
- **Échec de scan com_file_id** (0x04 et IF) : index 255 → `1 << 255` sur 32 bits = `0x80000000` (x86 shl module 32) — masque de cible "impossible", sans crash.
- **`memcpy` op 0x25** : source/destination **inversées** dans le pseudo-C Hex-Rays (`memcpy(ptr_texte, &BMI_SCAN_BUFFER[..], 24)` alors que l'asm pousse src= texte, dst= buffer scan en dernier) — se fier à l'asm : le buffer scan **reçoit** le texte. Attention en réécriture.

## 8. Où Hex-Rays masque la logique (liste précise)

1. **`if_right_condition_final` / `jump_value`** : déclarés `int` mais seuls les 16 bits bas sont valides ; les comparaisons mélangent `(u16)` et int — le pseudo-C est correct mais trompeur.
2. **`p_ai_subsection_init_code` (ebp)** : réemployé comme registre à tout-va (pointeur texte en 0x1A/0x22, valeur de retour de `CompareValues`...). La sémantique "paramètre d'entrée" n'existe qu'au prologue et à LABEL_373/374.
3. **`def_487EDC` partagé** avec le code de l'op 0x24 : le label "default" du switch externe est physiquement l'entrée du handler 0x24 ; Hex-Rays le présente comme "cases 10,16,20,33" — la table réelle (vérifiée) envoie bien 0x0A/0x10/0x14/0x21 vers 0x487EBA (sommet de boucle), pas vers 0x487EE3.
4. **Cases mortes du switch interne IF** (0x50–0x57, 0x60–0x67, 0xDC–0xE3, et 0x0A partiellement) : atteignables seulement si la table 0x48A204 produisait ces valeurs — elle ne le fait pas. Hex-Rays ne le montre pas.
5. **`memcpy` de l'op 0x25** : ordre des arguments rendu ambigu (voir §7).
6. **`byte_1D28E11/12/13`** : globals de mise en forme texte (type de message, id magie, compteur) — Hex-Rays les disperse ; ils forment un petit record partagé entre 0x29 et 0x2E.
7. **`BATTLE_SLOT_DATA[v93 - 4]` / `+opcode_param_1-3`** (IF sujet 0x14) : arithmétique de struct déguisée en index négatif — c'est `BATTLE_LOCAL_VAR[52*slot + (subj-0xD0)]` (dword).
8. **Prologue berserk** : le `do/while` sur `random_chara_target` réutilise `buffer_v7` comme base de slot ET comme futur masque (`BYTE1(buffer_v7)`) — illisible en pseudo-C.

## 9. Pseudo-C fidèle (squelette exact, non modernisé)

```c
uint8_t VM_ExecuteScript(uint32_t ebp_section /*@ebp*/, uint32_t slot,
                         uint8_t* code, int text_base, int text_off)
{
    uint8_t  cmd = 0;            uint16_t sec = 0;
    uint8_t  scratch = 0;        uint8_t  alt_param = 0;
    uint32_t tmask = 0;          uint8_t  has_text = 0;
    uint8_t  p1, p2, p3, tst;    uint16_t val, jmp;
    uint32_t diff = BMI71_LOW_MED_HIGH_LEVEL_BIS[71*slot];
    uint32_t abil_base = *(uint32_t*)BATTLE_SLOT_DATA[slot].monster_info_section; // G16: 1 deref

    if (AI_CURRENT_SECTION_INDEX == 1 && (BATTLE_SLOT_DATA[slot].status_1 & 0x20)) {
        if (CountAlivePartyMembers() == 255) { tmask = 0; p1 = 0; code = AI_VM_FALLBACK_BYTECODE; goto commit; }
        uint32_t t;
        do { t = (uint8_t)Battle_GetRandomInt() % 3; } while (BATTLE_SLOT_DATA[t].status_1 & 1);
        tmask = 1u << t; p1 = 0; code = AI_VM_FALLBACK_BYTECODE; goto commit;
    }

parse:
    { uint8_t op = *code++;
      if (!op) return 0;                        /* STOP */
      switch (op) {                             /* jpt_487EDC, 61 entrées */
      case 0x06: goto commit;
      case 0x0C: p1 = *code++; abil_base = /*(inchangé)*/;
                 { uint32_t i = 16*diff + p1;
                   cmd = *(uint8_t*)(abil_base + 4*i + 0x34);
                   sec = *(uint16_t*)(abil_base + 4*i + 0x36);
                   scratch = *(uint8_t*)(abil_base + 4*i + 0x35); }
                 if (!sec) goto parse;
                 goto commit_tail;
      /* ... 0x03/0x07 remplissent cmd/sec ; 0x04 remplit tmask ; 0x23: code += (int16)jmp ; ... */
      case 0x02: { p1 = code[0]; p2 = code[1]; p3 = code[2];
                   val = code[3] | (code[4] << 8);
                   jmp = code[5] | (code[6] << 8); code += 7;
                   if (p1 > 0xE3) goto parse;
                   switch (byte_48A204[p1]) {   /* table sujets -> handler */
                   case 0: /* HP% */ ...
                   case 2: if ((uint8_t)Battle_GetRandomInt() % p2 /*cmp*/ val) goto parse; /* sinon chute */
                   /* ... chaque handler: si condition FAUSSE -> code += jmp; goto parse; */
                   } goto parse;
      }
    }

commit:
    { uint32_t i = 16*diff + p1;
      cmd     = *(uint8_t*)(abil_base + 4*i + 0x34);
      sec     = *(uint16_t*)(abil_base + 4*i + 0x36);
      scratch = *(uint8_t*)(abil_base + 4*i + 0x35);
      if (!sec) goto parse; }
commit_tail:
    BATTLE_SLOT_DATA[slot].target_info_mask = tmask;
    if (cmd == 2)      tmask |= ComputeMaskFromDefaultTarget(K_MAGIC[sec].defaultTarget);
    else if (cmd == 4) tmask |= ComputeMaskFromDefaultTarget(K_ITEM[sec].targetInfo);
    else if (K_ENEMY_ATTACK[sec].attackFlags & 0x80) tmask |= 0x4000;
    BattleAction_GetText(slot, cmd, sec, has_text, alt_param, tmask, scratch);
    BattleAction_ResolveTargetAndHitCount(tmask);
    if (BOOL_TARGET_CHOOSEN) return 1;          /* VM stoppée, action lancée */
    SetPhaseFlag(5); EnqueueActionPresentation(ATTACK_HIT_COUNT - 1);
    ACTION_EVENT_GROUP_INDEX[ATTACK_HIT_COUNT*5] = 0;
    if (BACK_PREEMPTIVE_INFO_3) { /* enqueue Odin/Gilgamesh cmd 0xF7 ; clear flags */ }
    SetPhaseFlag(6); EnemyAI_SyncAIVarsToSlot(slot);
    goto parse;
}
```

## 10. Ambiguïtés restantes & points à examiner pour les lever

1. **Taille/terminateur de `AI_VM_FALLBACK_BYTECODE`** (0x1D2A21D, lu 0xFF×16) : vérifier les octets suivants jusqu'au premier 0x00 et qui réinitialise `esi` après le chemin berserk (le flux 0xFF est une suite de no-ops ; si aucun 0, lecture hors zone). → `get_bytes 0x1D2A22D..` + xrefs à ce symbole.
2. **IF sujet 2** : `idiv` signé avec `param` potentiellement 0 → division par zéro possible si un script émet `IF 2, 0, ...`. Chercher dans les données (`ai_subcode`) une occurrence. → dump des scripts d'encounters.
3. **Sens exact du `memcpy` op 0x25** et du champ de 24 octets (`BMI_SCAN_BUFFER[71*slot-213]`) : confirmer src/dst dans l'asm (push order à 0x4885F0–0x488605) et le rôle de "Scan" (analyse) côté affichage.
4. **Cases mortes du switch IF interne** : confirmer qu'aucun autre site n'appelle ces blocs (0x489711, 0x48965B, 0x4895B7) — xrefs_to ces adresses.
5. **Sémantique `K_ENEMY_ATTACK.attackFlags & 0x80` → 0x4000** : croiser avec `BattleAction_ResolveTargetAndHitCount` (0x48E830) pour savoir ce que fait le bit 0x4000 (direction "allié→ennemi" inversée ?).
6. **`BACK_PREEMPTIVE_INFO_3` / `byte_1D28DCD/DCE`** : qui les positionne (contre d'Odin/Gilgamesh esquivé ?) — xrefs_to ces globals.
7. **Différence 0x1F vs 0x34** : 0x1F enchaîne un second relay 0x71 (anim) + `UnlockActionLatch` + phase 6 ; 0x34 non. Vérifier si 0x34 dépend d'un relay 0x71 posé ailleurs (ex. 0x35) dans les scripts réels.
8. **`has_text_pending`** n'est jamais mis à 1 dans cette fonction (seulement lu) → trouver le producteur (probablement un opcode d'une autre VM ou un paramètre d'entrée dérivé).
9. **Sentinelle `byte_1D2817B`** : recalculer exactement `BATTLE_SLOT_DATA + 8*208 + off(com_file_id)` pour valider que les scans couvrent bien les 8 slots.

**Confiance globale** : table d'opcodes et flux de contrôle = FACT (vérifiés contre la jumptable brute) ; noms sémantiques des cibles/sujets = STRONG INFERENCE (cohérence multi-sources G13–G22) ; comportement hors scripts canoniques (cases mortes, sentinelles) = à traiter comme SPECULATION tant que les données de jeu n'ont pas été balayées.
