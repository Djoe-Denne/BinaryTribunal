`core`/`application` → `abi`. C’est un écart de **clôture** :

- « live-promoted / `satisfied=true` » = sous-ensemble **P1**
  démontré, pas le milestone canonique entier ;
- les `required` de `evidence-policy.toml` sur-déclarent parfois
  des unités encore ouvertes ;

  ([[projects/final-fantasy-viii-reimaginated/references/g14-g17-red-team-2026-08-27]]) ;
- G22 est un brouillon honnête (`satisfied=false`) dont le code
  n’implémente pas encore U22.1–U22.8.

## Findings

### F1 — « Milestone passé » ≠ gate canonique

Déjà écrit dans les pages P1, mais les manifests le nient.

`[promotion.G19].required` contient `u19-1-through-u19-6-offline`
alors que U19.4 est décoché et SQ-G19-001 ouvert. L’optionnel
`card-devour-mug-persist-only-after-sq-g19-001` est la vérité ;
le `required` est trop large.

Même motif G20 : `u20-1-through-u20-8-offline` required,
U20.8 ouvert, SQ-G20-001 ouvert. La page P1 le dit (« Gate G20
(this batch): claimed routes only »).

`validate_contracts.py` vérifie ownership + hashes d’enveloppes,
pas les cases du wiki. Donc CI peut rester verte sur une
sur-déclaration.

**Classe :** contradiction / fail-closed documentaire.
**Pas un bug runtime.**

### F2 — Compteurs native tamponnés (régression G18–G21)

La review du 27 a forcé G15/G16/G17 à **mesurer**
`native_*_vm_calls`. G16 le fait encore via
`native_ai_vm_calls_.load(...)`.

| `runtime-x86/src/g20_limit_families.cpp:305` et `:329` | idem |
| `runtime-x86/src/g21_battle_data.cpp:196` | idem |

Les enveloppes live G18/G19 portent `native_gameplay_calls=0` /
`native_helper_calls=0` et `memory_hash_before/after=0x00000000`.
Zéro n’est pas une mesure s’il n’existe pas de hook qui
incrémente le compteur.

G22 a appris la leçon côté fill (`test_g22` : « does not stamp
armed or native helper counts ») mais `native_helper_calls`
reste initialisé à 0 dans `derive_init_state` sans audit runtime

**Classe :** angle mort de gouvernance des témoins.
**Même famille que le 27.** Ne justifie pas une re-promotion
historique ; bloque un futur « zero native helpers » pris au
sérieux.

### F3 — Enveloppe G18 shutdown n’est pas le même objet

`p1-g18-host-post-shutdown-2026-08-28.json` (1052 o) est un
snapshot field/HUD (`frame_bytes`, `hud_preimage_matches`), pas
un envelope runtime (`dll_sha256`, `verdict`, `call_audit`).
G19+ shutdown sont des envelopes complets (~12 Ko).

`[promotion.G18].canonical_envelopes` liste ce fichier mince à
côté du suite host-offensive. Le pack « completion » de
l’après-midi (DLL `b6db8a89…`, PID 58056) existe en evidence
mais n’est pas canonique. Le hash ownership reste le matin
`34204e43…`.

**Classe :** reporté si on accepte « matin = canonique » ;
angle mort si on lit `canonical_envelopes` comme « le dernier
host-commit ».

### F4 — `0x3C` ModHp : wrap uint32 test-locké

Implémentation :

```text
hp = uint32(int32(hp) + int16_delta)
```

`tests/offline/test_g16.cpp` : HP 500 + (−5) = 495 ; HP 1 + (−5)
= `0xfffffffc` (« 0x3c wraps uint32 »).

[[projects/re-ff8/references/enemy-ai-opcodes]] dit seulement
`current_hp += (int16)delta` à `0x489F30`. Pas de clause
overflow/clamp. U16.3 est coché.

Si le native clamp à 0, le test a fossilisé un faux positif.
Si le native wrap 32-bit, c’est de la fidélité. **Non tranché.**

**Classe :** angle mort statique (fermable en IDA sur
l’addition, sans live). Pas une clôture G16 à rouvrir tant que
le wrap n’est pas contredit.

### F6 — Loi des couches : conforme

Graphe CMake :

```text
ff8iso_core → (rien d’abi)
ff8iso_application → ff8iso_core + ff8iso_contracts
ff8iso_abi → ff8iso_contracts
ff8iso_runtime → application + abi
```

Zéro hit `ff8iso/abi`, `abi::`, `find_symbol`, `import_legacy`,
`LegacyBattleImage` sous `core/` et `application/`.
G22 `write_rva` / `find_global` restent dans
`runtime-x86/src/g22_battle_init.cpp`.

`RTK.md` est injecté par `@RTK.md` dans AGENTS Codex et **absent**
des deux arbres (`re-ff8` et Reimaginated). Rupture de
gouvernance locale, pas un leak de couche.
