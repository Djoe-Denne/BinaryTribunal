## Task: Clarify ATB Auto-Command Readiness Masks

### Setup For You

- Use an active battle where you can apply Berserk, Confuse-like states, Angel Wing, or other suspected auto-command statuses.
- Start with the target slot below full ATB, then let it naturally reach readiness while breakpoints are armed.
- Watch `status_1`, `status_2`, `flag_data`, ATB fields, and pending bytes across the readiness transition.
- Avoid opening the normal command menu for the tested slot unless the test is the non-auto baseline.

### Context

ATB increment, readiness, and command-menu enqueue are mapped, but some auto-command masks are not fully named. The key unknown is the identity of `status_2 & 0x2004000` in readiness routing.

### Known Anchors

- `BattleATB_TickAndReady` at `0x4842B0`.
- `BattleUI_InputPollAndMenuState` at `0x4A8772`.
- `BattleUI_EnqueueCommand(slot, 17, 128, 0)` at `0x4AD620`.
- `Battle_ProcessAutoCommand(slot)` is used for auto-command readiness.
- `status_1 & 0x20` routes to auto-command and is likely Berserk.
- `status_2 & 0x2004000` also routes to auto-command, exact bit names TBD.
- `flag_data |= 0x04` for auto-ready, `flag_data |= 0x08` for menu-ready.

### Investigation Steps

1. Decompile `BattleATB_TickAndReady` around the readiness branch.
2. Identify every status bit that routes to `Battle_ProcessAutoCommand`.
3. Find writer functions for `status_2` bits `0x00004000` and `0x02000000`.
4. Confirm whether the bits correspond to Confuse, Charm, Berserk-like, Angel Wing, or another auto-action state.
5. Trace which command bytes are generated by auto-command states.
6. Check how auto-command state exits or clears.

### Runtime Evidence Plan

- Apply Berserk, Confuse-like, Angel Wing, and any status suspected of auto-command behavior.
- Break at `0x4842B0` and `Battle_ProcessAutoCommand`.
- Watch `status_1`, `status_2`, `flag_data`, pending action bytes, and command menu enqueue calls.

### Expected Output

1. Auto-command status bit table.
2. Readiness branch pseudocode.
3. Auto-generated command examples.
4. Clear/exit behavior for each auto-command state.
5. Updates for `docs/tech/systems/atb_system.md` and `docs/tech/reference/status_bits.md`.
